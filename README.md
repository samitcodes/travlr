# Architecture

In my full stack project, I used multiple frontend development approaches, including Express HTML, JavaScript, and a single-page application (SPA), each serving a different purpose. Express HTML relied on server-side rendering, where pages were generated by the backend and sent to the browser. This approach was simple to implement and worked well for basic, content-driven pages, but it required full page reloads for most interactions. JavaScript was used on the client side to add interactivity, such as form validation and asynchronous requests, improving the user experience without reloading the page. The SPA handled all routing and rendering in the browser, communicating with the backend through RESTful APIs. This resulted in a smoother and more responsive user experience, especially for data-heavy features, though it required more setup and a larger initial load. The backend used a NoSQL MongoDB database because it supports flexible, document-based data storage that works well with modern web applications. MongoDB stores data in a JSON-like format, which integrates naturally with JavaScript and REST APIs used by the frontend and SPA. Its schema flexibility made it easier to adapt the data model as project requirements changed, without needing complex migrations. Additionally, MongoDB is designed to scale efficiently, making it a strong choice for applications that may grow in size or complexity over time.
